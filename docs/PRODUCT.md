# PaperLingo 产品与交互设计

v0.2 在英语学习之外新增研究库、个人笔记、带证据的论文汇总与语义检索。完整信息结构和本地模型方案见 [v0.2 规划](V0.2_PLAN.md)，实际验收见 [v0.2 记录](VERIFICATION_V0.2.md)。

## 目标
把英文论文阅读中的真实障碍转化为个人学习材料。macOS 14+ 原生应用，面向 Apple Silicon；阅读内容、词库、模型、音频留在本机。首次下载模型、导入网页需要联网，日常翻译、发音、复习不依赖云 API。

## 主流程
1. 论文库：导入 PDF 或 HTTP(S) 链接，保存本地副本与阅读位置。PDF 使用 PDFKit 保留公式、图表、双栏；网页提取正文并保存快照。arXiv 摘要链接自动转换为 PDF。
2. 阅读：左侧导航，中间论文，右侧学习助手。原生选词、选句后预览选区，明确点击「翻译」才记一次查询，避免选区变化把一次查询累计多次。保留所在句、论文、页码。
3. 查阅：英译中、原文朗读、慢速播放。词/短语在成功翻译后自动进入词库；长句只记录查阅，点击「加入复习」才制卡。模型未就绪显示可操作的错误，不伪造翻译结果。
4. 生词本：搜索、按查询频率或到期排序，展示类型、来源、上下文、查阅次数、遗忘次数；可删除、跳回来源、导出 JSON 备份。
5. 每日复习：默认 20:30 提醒，每天约 10 分钟、最多 20 张卡。只从已到期项目中按遗忘次数、查询次数、逾期程度选取；认词卡先隐藏答案，听力卡先隐藏原文和译文，主动揭晓后用「忘记／模糊／记住／轻松」评分。
6. 本地引擎：显示 Ollama、TranslateGemma、OmniVoice 的真实可用状态；可启动/停止本应用拥有的进程、检查连接、查看日志，控制语速和美式/英式音色。首次模型下载使用项目内安装脚本，可查看下载进度。

## 信息架构
- 研究库（启动首页）：分类/标签、阅读状态、文献档案、AI 汇总、个人笔记及检索。
- 阅读空间：论文库 + PDF/正文 + 学习助手。
- 生词本：从真实查阅生成的单词、短语、句子，带来源与复习状态。
- 今日练习：认词/听力两种模式，固定当次队列，评分后切换下一项。
- 设置：模型状态、复习时刻、通知权限、数据目录、导出。

## 阅读交互改进
- 导航整行、论文列表空白区域、图标周围都属于可点击范围，图标目标至少 32 × 32 pt。收起的控件同时关闭命中测试，避免透明控件拦截正文操作。
- 两侧面板可以独立隐藏；标题与主工具栏合并，收起后正文获得完整宽度。面板宽度随窗口缩放；专注模式隐藏侧栏与标题，浮动工具栏自动隐藏，可通过顶部小按钮及快捷键恢复。
- 播放器作为右下角 overlay，与正文尺寸无关。暂停、接续、分段进度、错误与折叠在浮层内变化，均不改变 PDF/TextView 的布局高度。
- 网页选区合并 120 ms 内重复事件，用真实 UTF-16 选区范围提取附近句子，在后台处理短窗口，避免对整篇论文反复分句。多个相同单词取实际选中位置的上下文。

## 学习规则
- 标准化：合并空格、PDF 跨行断词、大小写和边缘标点。原文保留，术语如 state-of-the-art 不去掉连字符；不做不可靠的词干合并。
- 词、短语、句子分别分类，同一标准化文本共享一张卡，多次来源单独保存。
- 查询记录与复习日志写入 SQLite 事务；已有熟词再次查询时重新到期，反映真实遗忘。
- 间隔：初次到期立即；忘记 10 分钟、模糊 1 天；记住依次 1、3、7、14、30、60 天；轻松提升一级。不是经过实验校准的 FSRS，后续可替换。
- 队列优先级：遗忘次数 × 4 + log2(查询次数+1) × 2 + 逾期天数（最多 30）。每天 20 张上限，重查不凭空增加遗忘次数。
- 听力使用个人词条及原论文例句；评分与认词共享掌握度，日志标注练习模式。音频按文本、音色、语速与模型签名缓存。

## 技术架构
SwiftUI/AppKit → PDFKit/正文 NSTextView → SQLite（原论文、词条、查询事件、复习事件）

本地翻译：Swift URLSession → 127.0.0.1:11434 → Ollama TranslateGemma 4B；使用官方翻译提示格式，默认 en → zh-Hans。4B 量化包约 3.3 GB。中文含义与论文上下文并列呈现；短语上下文语义可能需要用户核对。

本地发音：Swift URLSession → 127.0.0.1:8765 → Python OmniVoice 0.2.1 → PyTorch MPS（不可用时 CPU），16 diffusion steps。模型按需加载；推理串行防止统一内存峰值，播放与下一段推理并行。

`POST /speak/stream` 返回 NDJSON：`start(total)` → `audio(index, text, audio=base64 WAV)` 逐段 flush → `done`。先按英文句末分割，识别常见缩写和小数；长句再按逗号/分号/词边界切分，首段最多 120 字符，后续最多 160 字符。首段解码后立即传回客户端，不等待整段波形。后续复用首个足够长的生成片段作为固定音色提示，并缓存每段 WAV；客户端用 AVAudioPlayer 按序衔接。`/speak` 保留用于诊断和整段基准对比。

每次朗读拥有独立 UUID；`POST /cancel` 能处理早于流注册的取消，GPU 锁等待与每段前后检查取消状态。正在执行的小段推理不强行中断，完成后停止剩余工作。客户端清空待播放队列，忽略旧请求响应和旧播放器回调，避免快速切换后串音。可选 macOS 系统语音用于模型安装期间体验，界面明确标注，不冒充 OmniVoice。

数据默认 ~/Library/Application Support/PaperLingo；开发/测试可用 PAPERLINGO_DATA_DIR 隔离。开发版模型与 Python 位于项目 .runtime，通过构建时写入的配置定位；移动项目后需重新构建。完整离线版将模型和 Python 放入 app，并将可写状态保留在用户目录，整个 app 可在退出后搬迁。

提醒使用 macOS 本地通知，用户在应用内主动授权；权限未授予则仅显示应用内到期列表。系统负责已安排的每日提醒，应用退出后仍可提醒；休眠/专注模式由 macOS 决定展示时机。通知不自动播放语音，点击进入当日练习。

## 第一版边界
支持含文字层的 PDF，扫描 PDF 显示需要 OCR 的提示。网页正文提取适用于服务端 HTML，登录墙、JavaScript 动态正文可改为浏览器打印 PDF。没有云端同步、账号、口语评分、全篇自动翻译。首版不训练个人模型，不用查询频率推断通用词频。

## 验收
真实 PDF 选区与上下文；网页导入及重启恢复；成功翻译才写查询日志；重复查询累计但单次点击去重；离线翻译和 OmniVoice 真实输出；听力先隐藏文本；四级评分决定下次时间；20:30 通知可授权、关闭、调整；SQLite 重启与 JSON 导出；失败明确呈现且不丢原词库。

## v0.1 离线分发

- arm64/macOS 14+ DMG 内为完整自包含 `.app`，包含两个模型、音频 tokenizer、Ollama、独立 CPython 和全部 Python 推理依赖。
- 原 venv 扁平化为嵌入式 Python 的 site-packages，仅保留相对的解释器链接；模型快照解引用为独立实体文件，不依赖开发机 HF 缓存。
- 分发配置为 `runtime=bundled`，模型标记使用 `models/OmniVoice` 相对路径。开发模式绝对 `.runtime` 配置仍兼容。
- 通过 RuntimePaths 把不可变资源和用户可写状态分开。Ollama 使用用户模型目录中的逐个权重链接及独立 manifest 副本，metadata、日志、HF 和音频缓存只写用户 Application Support。
- Python 禁用 pyc 写入与用户 site-packages。应用移动后更新模型链接，模型权重不重复复制到用户目录。
- 个人数据库与论文不进入分发包；各模型许可、作者信息及 Gemma Notice 随包保留。当前为本机 ad-hoc 签名，未进行 Developer ID 公证。
